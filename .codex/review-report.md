# 2026-04-28 修复复核

本次修复对准了报告里最核心的三处问题。

第一处是任务终态一致性。现在完成、失败、取消都会先做带重试的终态写库。写库失败时不会马上把任务从内存追踪表删除，而是交给后台补偿同步。数据库里长期残留 running 的概率被明显压低了。额外加的 orphan 收敛逻辑，也能把已经脱离内存追踪的陈旧 running 任务自动改成 error。

第二处是订阅更新任务的取消链路。任务 context 已经从 scheduler 传进 `node/sub.go`。HTTP 下载、解析后收口、节点遍历和批量写库前都能感知取消。取消后不会再误报失败或完成，状态由 TaskManager 的 cancelled 终态统一收口。

第三处是用户可见的停止入口。前端任务进度面板和任务页表格都已允许 `sub_update` 显示停止按钮，不再只有 `speed_test` 能停。

这次修复还顺手补了同机场订阅更新互斥，避免 cron 和手动触发把同一个机场任务叠起来跑。

本地验证上，任务系统相关包测试通过。全量 `go test ./...` 仍有既有 `api` 并发失败，问题在订阅导出链路，不是这次修复新带出来的回归。
